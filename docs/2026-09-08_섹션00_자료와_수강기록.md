## 크롤링 제한의 효과와 한계

1. 모든 18개 HTML에 robots/googlebot 메타 `noindex,nofollow,noarchive,nosnippet,noimageindex`를 넣었다. 메타 지시를 읽고 따르는 검색엔진에 색인·표시 제한 의사를 전달한다.
2. `dist/robots.txt`는 모든 User-agent에 `Disallow: /`를 선언한다. **반드시 해당 출처의 /robots.txt에서 제공되어야 한다.** 프로젝트 하위 경로에 있는 파일은 루트 규칙이 아니다.
3. 현재 GitHub Pages URL은 `https://inflearn-basilry.github.io/202609_AI_Fullstack_Deploy_Course/`이다. 여기의 robots.txt는 하위 경로에 배포되므로 도메인 전체 크롤링 정책을 설정하지 못한다. 적용하려면 루트 사이트 저장소의 robots.txt에 `Disallow: /202609_AI_Fullstack_Deploy_Course/`를 넣거나, 독립 도메인 루트 호스팅에서 제공해야 한다. 루트 사이트·도메인·배포 구조는 이번 작업에서 변경하지 않았다.
4. robots.txt로 접근을 막으면 검색엔진이 페이지의 noindex 메타를 읽을 수 없을 수 있다. 이미 색인된 URL의 제거가 필요하다면 검색엔진별 제거 절차도 별도로 확인해야 한다.
5. robots.txt와 메타는 접근 제어가 아니다. 규칙을 무시하는 봇, 일반 HTTP 다운로드, 공개 GitHub 저장소의 소스 복제까지 막지 못한다. 실질적인 비공개가 필요하면 인증된 호스팅과 저장소 접근 제한이 필요하다. 이번 작업에서 로그인·요금제·저장소 공개 범위를 바꾸지 않았다.

근거: [Google robots.txt 작성·루트 위치 규칙](https://developers.google.com/crawling/docs/robots-txt/create-robots-txt), [Google noindex와 크롤링 차단의 관계](https://developers.google.com/search/docs/crawling-indexing/block-indexing).
