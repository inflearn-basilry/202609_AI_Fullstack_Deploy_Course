# 포스팅 문체 가이드 — 뜻을 직접 쓰기

## 출처와 적용 범위

사용자가 2026-09-09에 첨부한 스크린샷에서 읽을 수 있는 내용을 추출했다. 화면 위쪽의 잘린 문장과 앱 UI 문구는 제외했다. 화면에 한국어 번역문을 소개하는 문장은 있지만, 실제로 보이는 프롬프트 본문은 영어뿐이다. 아래 한국어 번역은 추출한 영어 원문을 바탕으로 새로 작성했다.

사용자는 이 지침을 앞으로 이 작업 폴더에서 포스팅을 작성할 때 적용하도록 요청했다. 스크린샷의 Claude Code·`CLAUDE.md` 활용 팁은 출처의 설명으로 보존하며, 이 작업 폴더에서는 `AGENTS.md`가 이 문서를 참조하도록 구성한다.

## 이미지에서 추출한 영어 원문

> "Mannered prose substitutes metaphor and flourish for direct statement. Instead of "a parameter worth varying," the mannered writer produces "a dial worth turning." Instead of "this point still matters," they write "this point earns its keep." The phrases exist to display the writer, not to convey the idea, and readers can tell. That is why mannered prose irritates: it makes the reader work harder so the writer can perform. It is also imprecise. Metaphors drag in connotations the writer did not choose and cannot control. The fix is to say what you mean. When a literal phrase is available, use it."

## 한국어 번역

기교를 과하게 부린 문장은 직접적인 설명을 비유와 장식적인 표현으로 대신한다. 그런 작가는 ‘바꿔 볼 만한 매개변수’를 ‘돌려 볼 만한 다이얼’이라고 쓰고, ‘이 점은 여전히 중요하다’를 ‘이 점은 제 몫을 한다’고 쓴다. 이런 표현은 생각을 전달하기보다 작가를 돋보이게 하려고 존재하며, 독자도 그것을 알아챈다. 그래서 이런 문체가 거슬린다. 작가가 기교를 부리도록 독자가 더 애써 읽어야 하기 때문이다. 정확하지도 않다. 비유에는 작가가 선택하지 않았고 통제할 수도 없는 연상과 함의가 따라온다. 해결책은 뜻하는 바를 그대로 말하는 것이다. 뜻을 직접 나타내는 표현이 있다면 그것을 써라.

## 실제 작성 규칙

1. **뜻을 먼저 정한다.** 각 문장에서 독자에게 전달할 사실, 생각, 감정이 무엇인지 분명하게 한다.
2. **직접적인 표현을 우선한다.** 독자가 비유를 해석해야 뜻을 알 수 있다면, 실제로 무엇이 달라지고 무엇을 하려는지 풀어 쓴다.
3. **장식을 덜어 낸다.** 표현을 지워도 정보나 감정이 달라지지 않고 문장이 더 명확해진다면 지운다.
4. **구체적인 주어와 동사를 쓴다.** ‘가능성의 지평이 열린다’보다 누가 무엇을 할 수 있게 됐는지 적는다.
5. **감정도 구체적으로 쓴다.** 기대나 불안을 없애지 않는다. 무엇 때문에 기대하거나 불안한지 설명한다.
6. **비유의 필요성을 따진다.** 모든 비유를 금지하는 규칙은 아니다. 실제 이해를 돕는 비유만 사용하고, 뜻하지 않은 함의를 만드는지 확인한다.
7. **사실과 상상을 구분한다.** 개인적인 꿈과 전망은 그에 맞는 표현으로 쓴다. 해 보지 않은 일을 경험담처럼 쓰거나, 아직 없는 성과를 만들어 넣지 않는다.
8. **다른 글을 자동으로 읽지 않는다.** 스타일 분석이나 어투 모방을 목적으로 기존 포스팅을 훑지 않는다. 사용자가 참고를 요청한 범위에서만 읽는다.

## 한국어 적용 예시

아래 예시는 이미지에 있던 문장을 옮긴 것이 아니라, 작성 원칙을 적용하기 위해 새로 만든 예시다. 실제 글에서는 맥락과 확인된 사실에 맞게 조정한다.

| 장식적이거나 모호한 표현 | 뜻을 직접 쓰는 표현 |
| --- | --- |
| 가능성의 지평이 열렸다. | 혼자서는 미뤄 뒀던 기능을 직접 만들어 볼 수 있게 됐다. |
| AI 경제의 물결에 올라타고 싶다. | 에이전트가 유료로 사용하는 서비스를 만들고 싶다. |
| 맥락이 흐르고 가치가 순환하는 생태계 | 에이전트가 필요한 정보를 요청하고, 받은 서비스에 비용을 지불하는 구조 |
| 내 경험이 새로운 옷을 입는다. | 현업에서 배운 내용을 강의로 정리하려 한다. |
| 작은 씨앗이 미래의 숲이 되기를 바란다. | 처음 만든 기능을 사람들이 다시 사용하는 서비스로 키우고 싶다. |

## 제출 전 확인

- 독자가 문장을 한 번 읽고 뜻을 이해할 수 있는가?
- 비유를 평이한 문장으로 바꾸면 더 정확해지는 곳은 없는가?
- 분위기만 더하는 문구나 같은 주장의 반복은 없는가?
- 글에 담긴 경험, 감정, 계획이 사용자가 제공한 내용과 일치하는가?
- 참고를 요청받지 않은 다른 글을 불필요하게 읽지 않았는가?
- 검토용 초안을 지정된 폴더에 저장하고 발행 전 상태로 두었는가?
